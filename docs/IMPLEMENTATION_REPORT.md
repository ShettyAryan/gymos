# GymOS: implementation report

**Date:** 2026-10-11 · **Stack:** Expo SDK 54 (`expo` ~54.0.37, React Native 0.81.5, React 19.1.0) · TypeScript 5.9 strict · runs in Expo Go 54 · expo-router · expo-sqlite · Supabase Free · Groq Free

| Area | Status | Notes |
|---|---|---|

What the automated tests cover:
- **Rules:**
  - progression boundaries (17 cases);
  - Adaptive Day, including the PRD's 20-minute leg-day example, rest never being cut, the plan snapshot not being mutated, infeasible requests and determinism;
  - the session state machine and completion classification;
  - PRs, streaks and the calendar (rest days, reschedules, excused skips, version windows, DST-safe dates and time zones);
  - XP idempotency keys, levels, units.
- **Local data:**
  - migrations: idempotent, and refusing to run against a newer schema;
  - outbox atomicity and rollback;
  - change coalescing;
  - **persistence across a simulated restart, and an active workout surviving an abrupt close.**
- **Workflows:**
  - planned, adapted, partial and freeform sessions;
  - finishing twice adds no extra XP;
  - award replay;
  - substitution after sets were logged;
  - undo;
  - excluding paused time;
  - rejecting invalid sets;
  - habit actions;
  - reschedules.
- **Sync** (in-memory server with the same rules as the SQL):
  - an offline write followed by sync;
  - a timeout after the server already committed, with no duplicates on retry;
  - expired login;
  - the bounded retry limit;
  - crash recovery;
  - restore on a new device without duplicate XP;
  - conflicts, plus both ways of resolving them;
  - the photo upload and delete queue.
- **Supabase SQL** (real Postgres in WASM):
  - RLS isolation;
  - anonymous access denied;
  - `sync_push` idempotency and conflict reporting;
  - server-side uniqueness of award keys;
  - the private bucket and per-user storage folders;
  - quota functions closed to clients;
  - `delete_my_cloud_data` scoping.
- **AI proxy** (mocked Groq):
  - auth, consent and policy version;
  - strict request validation (e.g. a `photos` field is rejected);
  - the per-user quota;
  - falling back on 429 (honouring `retry-after`), 5xx, timeouts and retired models;
  - all models exhausted, with no other provider contacted;
  - the circuit breaker and header-based pausing;
  - malformed output discarded;
  - conversion to strict JSON Schema.
- **AI client:** consent gating, minimal context (no name, age, weight, photos or paths), and an AI draft that stays a draft and passes validation.
- **UI component:** a set is on disk *before* the UI acknowledges it, and invalid sets are not saved.

## 3. Not run here (needs your setup)

- **App on a physical device or emulator.** No Android SDK, emulator or Java is available here, and Windows can't run iOS simulators. Run `docs/MANUAL_TEST_CHECKLIST.md`.
- **Native builds.** `expo run:android` needs Android Studio and a JDK. iOS needs macOS or EAS.
- **Live Supabase.** The migration was tested in PGlite with stand-ins for the auth and storage schemas. Edge Functions were not deployed. The Supabase client transport (`supabaseTransport.ts`) is not covered by automated tests.
- **Live Groq.** The proxy core is tested with mocks only. Real strict-mode acceptance of the generated JSON Schemas should be confirmed with one live call per task.

## 4. Manual setup still required

1. Supabase project → `supabase link` → `supabase db push` → `supabase functions deploy ai-coach delete-account`.
2. App `.env` with `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY`.
3. Groq API key, set as an Edge Function secret (`supabase secrets set --env-file supabase/functions/.env`). Optionally enable Zero Data Retention.
4. Optional: decide on email confirmation in Supabase Auth.
5. Re-run the release check in `docs/FREE_TIER_LIMITS.md` before any release.

## 5. Known limitations

- The schedule is weekday-based. Rotations not tied to weekdays (e.g. "every 3rd day") aren't supported yet.
- The rest timer is transient: it resets if the process is killed. Logged data is never lost this way.
- One primary editing device is assumed. Conflicts are resolved per record, not per field.
- The JSON export doesn't embed photo files. Photos restored on a new device download on tap.
- If the app crashes after a photo upload but before its path is saved, an orphaned private object can remain (it is never public).
- The progression engine doesn't auto-progress distance work, and for pure-bodyweight exercises at the top of the range it suggests a harder variation instead of adding load.
- The starter library is deliberately modest (61 exercises). Add custom exercises for anything missing.
- Reminders use local notifications only, and are re-scheduled when a programme is approved.
- The AI coach needs the cloud backend and sign-in. Without them, Mock AI is available for development only.

## 6. Costs outside the free stack

- **Runtime software cost: $0.** Every dependency is free/open-source. Supabase and Groq are used on their free plans, with no payment method and no paid fallback.
- **Possible costs:**
  - Google Play developer registration fee and Apple Developer Program membership, needed for store distribution.
  - EAS builds beyond the free quota (optional; local builds are free).
  - Upgrading Supabase or Groq if usage outgrows the free tiers. This is never automatic.
  - Supabase free projects pause after 7 days of inactivity; restoring is free but manual.
